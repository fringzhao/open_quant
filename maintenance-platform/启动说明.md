# OpenQuant 数据维护平台启动说明

## 1. 项目说明

数据维护平台由两个服务组成：

| 服务 | 技术栈 | 端口 | 访问地址 |
| --- | --- | --- | --- |
| 前端 | Vue 3 + Vite | 8071 | <http://127.0.0.1:8071> |
| 后端 | Python Flask | 8072 | <http://127.0.0.1:8072> |

后端默认维护仓库根目录下的 `data.db` DuckDB 数据库。

## 2. 环境要求

- Python 3.12 或更高版本
- Node.js 20 或更高版本
- npm
- 项目根目录下存在 Python 虚拟环境 `.venv`

以下命令均假设项目位于：

```text
/Users/mac-zmh/code/github/open_quant
```

## 3. 首次安装依赖

### 3.1 安装后端依赖

打开终端，进入项目根目录：

```bash
cd /Users/mac-zmh/code/github/open_quant
source .venv/bin/activate
pip install -e .
```

### 3.2 安装前端依赖

```bash
cd /Users/mac-zmh/code/github/open_quant/maintenance-platform/frontend
npm install
```

依赖已经安装过时，不需要重复执行本节命令。

## 4. 启动后端

打开一个终端窗口并执行：

```bash
cd /Users/mac-zmh/code/github/open_quant
source .venv/bin/activate
python maintenance-platform/backend/app.py
```

出现以下信息表示后端启动成功：

```text
Running on http://127.0.0.1:8072
```

可访问健康检查接口确认服务状态：

<http://127.0.0.1:8072/api/health>

不要关闭这个终端窗口，否则后端服务会停止。

## 5. 启动前端

另开一个终端窗口并执行：

```bash
cd /Users/mac-zmh/code/github/open_quant/maintenance-platform/frontend
npm run dev
```

出现以下信息表示前端启动成功：

```text
Local: http://127.0.0.1:8071/
```

在浏览器中打开：

<http://127.0.0.1:8071>

## 6. 停止服务

分别进入运行前端和后端的终端窗口，按下：

```text
Control + C
```

即可停止对应服务。

## 7. 数据库注意事项

DuckDB 不支持多个进程同时持有同一个数据库的写连接。

执行“同步最新数据”前，请先断开 TablePlus、DBeaver 等数据库工具对以下文件的连接：

```text
/Users/mac-zmh/code/github/open_quant/data.db
```

如果数据库仍被占用，页面会提示：

```text
数据库正被其他程序占用，请关闭 TablePlus 等连接后重试。
```

关闭数据库工具中的连接后，再重新查询或同步即可。

## 8. 使用其他数据库文件（可选）

后端支持通过环境变量临时指定其他 DuckDB 文件：

```bash
cd /Users/mac-zmh/code/github/open_quant
source .venv/bin/activate
OPEN_QUANT_DB_PATH=/absolute/path/to/data.db python maintenance-platform/backend/app.py
```

未设置 `OPEN_QUANT_DB_PATH` 时，默认使用项目根目录的 `data.db`。

## 9. 生产构建（可选）

需要检查或生成前端生产文件时执行：

```bash
cd /Users/mac-zmh/code/github/open_quant/maintenance-platform/frontend
npm run build
```

构建结果会生成在：

```text
maintenance-platform/frontend/dist
```

## 10. 常见问题

### 页面无法访问

检查前端终端中是否显示 `http://127.0.0.1:8071`，并确认该终端仍在运行。

### 页面提示请求失败

检查后端终端是否仍在运行，并访问 <http://127.0.0.1:8072/api/health> 确认接口状态。

### 端口已被占用

确认没有重复启动前端或后端，然后停止占用 8071、8072 端口的旧进程，再重新启动。

### 同步失败

依次检查：

1. 是否已断开 TablePlus 等工具对 `data.db` 的连接；
2. 当前电脑是否能够访问 AKShare 或 BaoStock 数据源；
3. 后端终端中是否输出了更具体的异常信息。
